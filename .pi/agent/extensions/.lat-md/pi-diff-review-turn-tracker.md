# Pi diff review turn tracker

This extension records per-turn bundles so later tooling can answer what changed in the repo during the last turn.

## Responsibilities

It derives a turn id from the incoming prompt when possible, kicks off one workspace-tree snapshot in the background at `agent_start`, captures a second at `agent_end`, and writes the net diff as the canonical turn artifact.

When `pi-ssh` is active it consumes the shared `pi-ssh` session runtime, maps the local cwd onto the remote repo through that session, and runs the same workspace-tree algorithm remotely through bounded git commands instead of path-by-path remote file reads.

At finalize time it writes the canonical observed diff artifact and mirrors the changed-path set into both `touched_paths` and `observed_changed_paths`. It may attach an optional fail-open `agent_change_report` generated by an external Codex summarizer, but that report is advisory only.

Its output is the `t`-mode history source used by [[pi-diff-review-tui]] and any other tooling that wants turn-scoped evidence.

## Turn lifecycle and artifact contract

`index.ts` owns lifecycle wiring only: derive a stable turn id, start capture on `agent_start` without blocking the model, finalize on `agent_end`, and reset on session boundaries.

A `pi-diff-review-turn-tracker/DISABLED` sentinel makes the entrypoint return before registering hooks. Delete that file and run `/reload` to re-enable tracking.

`lib/tracker.ts` owns the artifact contract. It stores the start-tree oid once background preparation finishes, captures the end-tree oid, diffs those two trees, and writes `latest.patch`, `latest.json`, and `latest-reviewable.*` through the shared artifact writer. If preparation is still running when the turn ends, `agent_end` waits there instead of delaying model startup.

The tracker is repo-scoped. It captures only the current cwd repo (or the resolved remote repo in SSH mode), not arbitrary files outside that repo.

## Workspace-tree capture

`lib/workspace-tree.ts` is the canonical capture backend. It builds a temporary git index, stages the current worktree with `git add -A -- .`, writes a synthetic tree with `git write-tree`, and then diffs start-vs-end trees.

This is the boundary other code relies on: the artifact reflects the net workspace delta for the turn, not `workspace vs HEAD`. Pre-existing dirty state is excluded automatically because both snapshots are taken from the current workspace state. Ignored files stay excluded because the temporary index still respects gitignore rules.

For SSH, the same tree-capture flow runs on the remote host through the shared `PiSshSession`. The contract is fail-fast, bounded git commands only. This code path must not crawl the remote repo with per-file stat/read calls because that blocks turn startup and makes SSH latency scale with repo size.

## Invariants

Tracking should reset on session start and shutdown so bundles do not leak across sessions.

`touched_paths` and `observed_changed_paths` currently mirror the same canonical changed-path set because ad-hoc tool attribution has been removed.

If present, `agent_change_report` must be validated against the artifact namespace, recomputed for exact mismatches (`missing_from_observed`, `missing_from_agent_report`), and discarded cleanly on invalid or contradictory output.

If the prompt came from Discord and includes a message id, that id should be preferred as the turn identifier so cross-surface tracing stays possible.

## Failure and recovery

If no stable external id is available, generate a local turn id explicitly rather than leaving the turn untracked.

If workspace-tree capture fails locally or remotely, log a concise diagnostic and skip persistence for that turn rather than hanging the session or emitting a partial artifact.

If the external summarizer times out, emits invalid JSON, reports out-of-namespace paths, or dirties the tracked repos, log a concise diagnostic and persist the canonical artifact without `agent_change_report`.

If a turn ends without meaningful repo changes, finalize a clean empty bundle instead of keeping stale state for the next turn.

## Change guidance

If you change bundle layout, canonical path derivation, advisory report schema, or turn-id rules, inspect [[pi-diff-review-tui]] because its `t` mode depends on the tracker’s last-turn bundle contract.

Keep this extension focused on capture and persistence; review UI policy belongs elsewhere.
